## Workloads and timing

The 21 fixtures contain 3,328 rows: 64 rotating rows per ordinary fixture and
2,048 distinct constraints for range-cache misses. The one-byte control repeats
nine adjacent numeric pairs in alternating directions, rather than using 64
distinct pairs. Inputs use strict ASCII full versions up to 256 bytes (the
longest is 208) and numeric cores/prereleases within JavaScript's safe-integer
range. Unsupported inputs are separate, non-ranked compatibility probes.

Each measured process runs 200,000 operations per fixture. One complete warm
process per engine precedes nine process-order rounds shuffled with seed
20261104. Each Node process also warms the same operation-specific loop with
at least 200,000 operations per fixture, rounded to full corpus passes. Every
input outcome and timed aggregate checksum is verified. Setup, input parsing,
normalization, preparsing and warmups are outside the timed loops.

Parsing includes constructing and observing complete results; native owned
values are dropped within timing. Node can retain immutable input strings and
its allocation/GC behavior remains included. Comparisons and matches reuse
parsed inputs. npm's default range cache stays enabled: 64-key warm sets and
2,048-key misses are reported separately. Misses are steady-state, not startup.
Rust comparison uses build-independent `cmp_precedence`.

Goose's separate native observation calls prevent folding and remain included.
Rust uses `black_box`; Node uses a global sink. These scaffolds and object
representations differ. Barrier-only controls are retained in the raw report
and are never subtracted. Small gaps should not be interpreted as intrinsic
function costs. Cold-start latency and allocation counts were not measured.

## Source and toolchain

The clean prepared checkout is
`f9c52cac10bcb644f28485ef07764dc5a64042f5`. Its production file, compiler pin,
all timed adapters, corpus and dependency locks match v0.1.1 byte-for-byte.
The benchmark driver adds preparation/reuse phases; it freezes sources and
hashes native adapters, compiler and Node executables, and installed Node
files before allowing measurements without rebuilding. These checks passed
before and after this run. [The preparation record](results/2026-11-05-preparation.json)
contains all identities, including the compiler executable hash.

The reused Goose compiler has clean source at
`eadca409f68210893f366e60d0c2f0dc29a339be`; it was not rebuilt or independently
attested during this audit. The recorded source/pin check and executable hash
identify what was used. No runtime dependency is added to goose-semver.

- CPU: Intel(R) Core(TM) Ultra 7 258V, affinity CPU 2.
- OS: Linux-7.2.11-arch1-1-x86_64-with-glibc2.44.
- Goose C compiler: gcc (GCC) 16.2.1 20260810; separate barrier translation unit, `-O2`, no LTO.
- Rust: rustc 1.101.0-nightly (822182db4 2026-10-13); release opt-level 3, thin LTO, one codegen unit.
- Node: v26.13.0; npm semver 7.8.6, lockfile installed with scripts disabled.

No CPU-native tuning was requested. The coordinator arranged a quiet local
window with the other owners; CPU affinity does not provide host isolation.
OS activity, frequency, caches, allocators and GC can still affect samples.

The one invocation ran from 2026-11-05T21:00:18.465809+00:00 to
2026-11-05T21:02:33.787951+00:00, 135.322 seconds including
preflight and cleanup, under a 180-second cap. Exit status was 0; the controller
was reaped and its process group was absent afterward. There were no retries.

## Reproduce

At the full prepared-checkout revision above, after `make setup`:

```sh
make bench-compare COMPARE_FLAGS='--prepare-only --cpu 2'
make bench-compare COMPARE_ITERATIONS=200000 COMPARE_ROUNDS=9 \
  COMPARE_FLAGS='--prepared --cpu 2'
```

Use an allowed CPU and the matching tools. An existing matching compiler may be
selected with `GOOSE=/absolute/path/to/goose`. Preserve the preparation manifest
and `.build/competitors/results.json`; inspect all samples and artifact hashes.
The 180-second controller bound describes this recorded experiment, not a
portable runtime requirement for reproducing it on a different machine.
